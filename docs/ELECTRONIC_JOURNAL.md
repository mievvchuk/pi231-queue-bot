# Електронний журнал

Mini App → Ще → Електронний журнал. Студент бачить лише власні записи.
Адміністратор у цьому розділі перемикається на журнал групи; доступ до
чужих записів і підтвердження перевіряються сервером у режимі адміністратора.

Предмети беруться зі спільного каталогу і розкладу, включно з фізичним
вихованням та філософією. Варіанти назви одного предмета об'єднуються
тим самим нормалізатором, що використовується для автоматичного запуску пар.
Викладачі не створюють окремих копій предмета в журналі.

Для кожного навчального року й семестру зберігаються лабораторні та
атестації з номером, оцінкою від 0 до 5 і приміткою. П'ятірка показується
червоним, оцінки нижче 3 — білими цифрами на чорному тлі. Є фільтри за
предметом, станом перевірки, а в груповому журналі — також за студентом.

Студент додає або редагує свій результат. Адміністратор підтверджує його
або повертає на виправлення з обов'язковим поясненням. Адміністратори також
можуть заповнювати записи за студентів, після чого явно підтверджують їх.
Редагування оцінки, примітки, предмета чи номера скидає підтвердження.
Повторні записи для тієї самої роботи й застарілі версії відхиляються.
Кожна зміна і рішення адміністратора зберігаються в `journal_events`.

Дати атестацій спочатку не задані. Власник може додати, змінити або прибрати
дату окремої атестації для предмета й семестру. Автоматичних розсилок немає.
Здача в черзі не виставляє оцінку й не підтверджує запис журналу автоматично.

Видалення зі списку групи позначає неактивний обліковий запис як видалений,
приховує його з поточних списків і відкликає браузерні сесії. Історія черг
і журналу залишається. Повернення через реєстрацію з тим самим Telegram ID
відновлює обліковий запис та власну історію. Активного учасника черги та
адміністратора видаляти не можна. Якщо потрібно заборонити повторний вхід,
для цього залишається блокування.

SQLite отримує додаткові міграції `users.deleted_at` і таблиць журналу;
PostgreSQL додає їх ідемпотентно при запуску. Чинні записи не видаляються.
