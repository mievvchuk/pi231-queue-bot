# Налаштування перед перезапуском

Справжні значення зберігайте в Environment хостингу або у локальному `.env`, який Git ігнорує. Повний шаблон: [`.env.example`](../.env.example). Не додавайте справжні токени, паролі або файли `.env` в PR.

## Обов'язково

| Ключ | Що встановити |
|---|---|
| `BOT_TOKEN` | Наявний токен цього бота з BotFather |
| `DATABASE_URL` | Наявне підключення до тієї самої бази й гілки Neon |
| `OWNER_ID` | Ваш Telegram ID; персонального значення в коді більше немає |

`INITIAL_ADMIN_IDS` — додаткові початкові адміністратори через кому. Якщо порожньо, використовується `OWNER_ID`. Це початкове наповнення лише порожньої таблиці; вже наявні адміністратори не замінюються.

## Необов'язково

- `MINI_APP_URL`: HTTPS-адреса цього самого Render-сервісу, наприклад `https://your-bot.onrender.com/app/`. Додає запуск Mini App з меню та додатковою кнопкою в головному меню; наявні кнопки залишаються. Без нового ключа або окремої бази. Порожнє значення не додає кнопку. Покроково: [MINI_APP.md](MINI_APP.md).
- `GROUP_CHAT_ID`: ID групи; значення, збережене через меню бота в базі, має пріоритет.
- `STUDENT_GROUP`, `TZ`, `NOTIFICATION_TIME`: група, часовий пояс і час вечірнього розкладу. Поточні типові значення: ПІ-231, Europe/Kyiv, 17:00.
- `RECOGNITION_PROVIDER`: auto / groq / openai / nvidia / ocr / disabled. `ocr` читає таблицю замін без ШІ і без ключа (OpenCV + RapidOCR на сервері, ~10 с на фото; модель ~8 МБ завантажується з modelscope.cn при першому розпізнаванні); це типовий вибір, якщо ключ не задано. `auto` обирає провайдера за префіксом ключа: `gsk_` → Groq, `nvapi-` → NVIDIA, інакше OpenAI-сумісний. Для явно обраного провайдера задайте його ключ у `RECOGNITION_API_KEY`; старий `OPENAI_API_KEY` також підтримується.
- `GROQ_MODEL`, `OPENAI_MODEL`, `NVIDIA_MODEL`, `GROQ_API_URL`, `OPENAI_API_URL`, `NVIDIA_API_URL`, `RECOGNITION_TIMEOUT_SECONDS`: параметри сервісу розпізнавання. Для NVIDIA (build.nvidia.com) `NVIDIA_MODEL` має бути vision-моделлю.
- `RECOGNITION_MAX_TOKENS` і `RECOGNITION_TIMEOUT_SECONDS` без значення: 4096 токенів і 120 с для NVIDIA, 900 токенів і 45 с для інших провайдерів. Явне значення в Environment має пріоритет. У шаблоні залишено попередні моделі, автоматичної зміни моделі немає.
- `HTTP_HOST`, `PORT`, `LOG_LEVEL`: параметри процесу. На Render не замінюйте PORT, який надає платформа.
- `POLLING_RETRY_SECONDS`, `POLLS_WATCH_INTERVAL`, `SCHEDULE_CHECK_INTERVAL`: інтервали повтору та перевірки фонових задач.
- `LAB_CATALOG_PATH`: JSON-каталог номерів лабораторних та їхніх лімітів, типово `data/lab_catalog.json`. Ключі відповідають ID предметів. Для вибраних робіт максимуми сумуються; особистий час студент вводить цілим числом від 5 хв до суми. `min_minutes` у каталозі — інформаційний орієнтир, `max_minutes` — верхня межа. Після редагування каталогу потрібен перезапуск процесу. Каталог не створює предметів або черг. Предмет без каталогу та черга типу consultation не запитують кількість, номери чи час. Старі `LAB_MIN_MINUTES` / `LAB_MAX_MINUTES` більше не використовуються.
- `SUBJECTS_PATH` задає шлях до файла предметів. `SCHEDULE_PATH` задає джерело одноразового імпорту розкладу в базу даних. Відносні шляхи рахуються від кореня проєкту. Без явного значення використовується наявний файл у корені або файл із `data/`.
- Після імпорту адміністратори редагують розклад у приватному чаті з ботом командою `/edit_schedule`. Оберіть день, тип тижня й номер пари. Надішліть назву предмета та за потреби викладачів, по одному на рядок у форматі `Ім’я | аудиторія`. Щоб прибрати заняття, надішліть `-`.
- `ENV_FILE`: альтернативний файл налаштувань; цю змінну задавайте перед запуском.

Тексти кнопок, SQL-міграції, правила черги, версія коду й базові предмети не є секретами та залишаються у відповідних модулях/JSON, а не в `.env`.

## Перевірка і запуск

З кореня проєкту:

```powershell
python -m queue_bot.check_config
python bot.py
```

Перша команда перевіряє налаштування й не підключається до Telegram або бази та не показує секретів. Альтернативний запуск: `python -m queue_bot`.

Команда хостингу `python bot.py` і `Procfile` не змінюються. Зміни доступні в PR до develop; звичайний Restart старого деплою з master не завантажить новий код. Спершу потрібен перевірений реліз із погодженими змінами або явне розгортання потрібної гілки.

## Збереження даних

Користувачі, черги, бани й історія залишаються у тій самій базі за `DATABASE_URL`. Міграції додають метадані лабораторних без видалення старих записів. Для старого запису номери залишаються невідомими: бот просить їх обрати, а не вгадує за попередньою кількістю. Для розкладу, імпортованого в локальний файл на хостингу, використовуйте постійний диск/шлях — звичайний файл тимчасового деплою не є резервною копією.

Перед релізом зробіть резервну копію робочої бази та збережіть власний файл розкладу. Робочий Neon, токени й деплой під час тестування не змінюються.
