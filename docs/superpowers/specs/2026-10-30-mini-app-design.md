# Telegram Mini App для ПІ-231

Статус: проєкт рішення для погодження. Додатковий інтерфейс до наявного бота; усі існуючі кнопки та сценарії в чаті зберігаються.

## Підхід

Mini App і HTTP API працюють у наявному aiohttp-сервісі Render, використовують ті самі сервіси Python і базу даних. Окремий сайт/сервер дав би незалежне розгортання, але додав би другий сервіс і синхронізацію налаштувань. Для поточного бота обрано один сервіс як простіше рішення. Це пропозиція реалізації, не зміна вже погоджених правил черг.

## Перша версія

- **Черги:** активні предмети та консультації, мої записи й місця, список учасників. Запис у кінець або на доступне місце; вибір лабораторних та особистого часу за чинними лімітами; редагування власного запису; здача або вихід. Одна/невказана лабораторна завершується одразу, кілька — з вибором зданих робіт. Обміни використовують чинні запити й строк 10 хв для запиту без відповіді.
- **Розклад:** сьогодні, завтра та вибрана дата, збережені заміни й загальні вказівки, які бот уже врахував.
- **Профіль:** ПІБ зі збереженого запису, мої черги, поточні обмеження. Незареєстрованому користувачу пропонується пройти реєстрацію через /start у боті.
- **Керування:** доступне лише адміністратору. Перемикання студентського й адміністративного режимів, відкриття/закриття запису, зміна позиції студента, позначення здачі, видалення з черги, бан на задану кількість днів і розбанування. ID видно лише в адміністративному режимі. Інші наявні адміністративні сценарії, включно з розпізнаванням фото та опитуваннями, залишаються доступними кнопками бота.

## Спільні правила

- Дії в Mini App одразу змінюють ту саму чергу, яку бачить бот; дані не копіюються в окрему базу.
- Збережено усі підтверджені предмети, ліміти, консультації, часткову здачу, повторюваність прийнятого обміну та тимчасові бани. Спільний бюджет 80 хв поки не вводиться: правило переповнення ще не погоджене.
- Нових автоматичних розсилок про оновлення немає. Наявні операційні повідомлення черг залишаються.
- Інтерфейс українською, пристосований для телефона, з підтримкою теми Telegram, явними станами завантаження/помилки та захистом від повторного натискання.

## Доступ і розгортання

- Сервер перевіряє підпис Telegram initData та строк дії; Telegram ID і роль визначаються на сервері. Дані користувача з непідписаного запиту не дають доступу.
- Кожна зміна перевіряє користувача, бан, власника запису, стан черги та актуальність запису. Адмінські операції окремо перевіряють права. Права не залежать від прихованої вкладки в браузері.
- Секрети залишаються на сервері; frontend отримує лише потрібні дані. ID інших учасників не повертаються студентському API.
- Кнопка «📱 Мініапка» додається до меню без видалення наявних кнопок. Публічну HTTPS-адресу задає MINI_APP_URL; без неї бот продовжує працювати попереднім способом.
- Той самий Render-сервіс і команда запуску; наявний healthcheck зберігається. Реальне підключення в Telegram перевіряється після розгортання за публічною HTTPS-адресою.

## Перевірка перед завершенням

Тести підпису й строку initData, відмови неавторизованим/заблокованим користувачам, чужих записів і студентського доступу до адміністративних дій; спільні дані API/бота; лабораторні, часткова здача, обміни та бани; збереження меню бота й healthcheck. Перевірка вигляду на вузькому екрані та регресійні тести наявного бота. Зміни комітяться й пушаться за AGENTS.md; розгортання production виконується окремо.
