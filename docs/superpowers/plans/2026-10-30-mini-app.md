# Additive Mini App Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan inline, followed by one fresh final review.

**Goal:** Ship the approved Mini App alongside every existing Telegram keyboard.
**Architecture:** Static HTML/CSS/JS in queue_bot/mini_app/static, an aiohttp API using existing synchronous domain services, signed Telegram initData per request. One shared connection/context; no DB transaction spans an await. The existing health server exposes readiness only after bot/DB initialization. No separate DB/service, frontend build step, API keys or new dependencies.
**Tech stack:** Python 3.11, aiohttp, aiogram, native browser JavaScript and Telegram WebApp SDK.
**Spec:** docs/superpowers/specs/2026-10-30-mini-app-design.md

## Constraints and rulings

- Preserve all keyboards; append one WebApp button only when MINI_APP_URL is configured as HTTPS. Static assets are served at /app/ and API at /api/miniapp/.
- InitData HMAC authentication uses Telegram's WebAppData algorithm; max age one hour, future skew 30 seconds, duplicate fields rejected. User/role always server-derived. No demo bypass in production.
- API mode=admin must be checked against current DB permissions; student payloads omit all other students' internal/Telegram IDs. UI uses own-entry marker and entry IDs solely as opaque mutation references, never displayed IDs in student mode.
- Unregistered users get /start instruction; banned users receive only their access error. Maintenance rules match the bot. Validate JSON shape, integer types, payload sizes, ownership, entry identity/revision, course exemptions and laboratory caps server-side.
- No update broadcasts. Reuse existing queue notifications for completion and swap messages. Mutation commits precede network awaits; notification failure cannot roll back a successful mutation.
- Keep current root health endpoint and startup/cleanup behavior. Configure the app context after DB and Bot construction, so pre-ready requests return 503.
- No production deploy, paid API request, live Telegram call or credentials change as part of development.
