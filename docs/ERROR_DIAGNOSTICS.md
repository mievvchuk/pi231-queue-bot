# Технічні помилки та баг-репорти

Кнопку мініапки прибрано з клавіатур бота: запуск залишається біля поля
введення Telegram. Стара текстова кнопка лише пояснює, де її відкрити.

Неочікувані помилки повідомлень, callback-кнопок, API мініапки та фонових
перевірок присутності, розкладу, опитувань і Telegram polling проходять
через `services/diagnostics.py`. Повний traceback, час UTC, код інциденту,
тип помилки та контекст записуються в журнал і надсилаються JSON-файлом
лише власнику через `admins.get_owner_ids`. Інші адміністратори цих файлів
не отримують. Повтор однакової помилки в тому самому контексті за 5 хвилин
не створює повторного сповіщення; кожен збій усе одно записується в журнал.

Студент отримує пояснення причини й наступної дії без traceback або SQL,
а також код інциденту. Очікувані бізнес-помилки, наприклад застаріла кнопка
або неприпустимий час, продовжують показувати конкретний текст перевірки.

До нового баг-репорту автоматично прикладається знімок останньої технічної
помилки саме цього студента. Він позначений як остання помилка, яка може
стосуватися іншої дії. Знімок зберігається в БД окремо від опису; повний
файл надходить тільки власнику. Буфер останніх помилок обмежений 200
користувачами і 24 годинами та очищується після перезапуску. Раніше надіслані
власнику файли й уже прикріплені знімки залишаються доступними. Якщо сама
БД або Telegram недоступні, діагностика залишається в журналі сервера.

Токени, URL бази, паролі та ключі маскуються. Значення SQL-параметрів,
тіла HTTP-запитів, заголовки авторизації та приватні поля форм не
прикладаються. Для PostgreSQL додається лише шаблон запиту через exception
notes. Адаптер екранує літеральний `%` перед створенням `%s`-плейсхолдерів,
відповідно до документації psycopg:
https://www.psycopg.org/psycopg3/docs/basic/params.html
