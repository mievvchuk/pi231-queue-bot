# Розробка за Gitflow

- `master` — стабільні релізи; чинний деплой залишається прив'язаним до цієї гілки.
- `develop` — інтеграція перевірених змін.
- `feature/<назва>` і `bugfix/<назва>` — від `develop`, PR повертається в `develop`.
- `release/<версія>` — від `develop`, після перевірки зливається в `master` та назад у `develop`, реліз позначається тегом.
- `hotfix/<назва>` — від `master`, виправлення повертається в `master` і `develop`.

Не створюйте порожні гілки feature/release/hotfix наперед. Створюйте їх для конкретної роботи. Не переписуйте історію основних гілок.

## Перевірки PR

`Tests / test` запускає pytest на SQLite та окремому PostgreSQL 16. PostgreSQL-тести створюють випадкову схему тільки в базі з `TEST_DATABASE_URL` та видаляють лише цю схему. Ніколи не задавайте робочий DATABASE_URL як TEST_DATABASE_URL.

Для `master` і `develop` у Settings → Rules / Branches рекомендується заборонити force-push і видалення гілок, вимагати PR та успішний `test`. Один незалежний review бажаний для команди; для одноосібного репозиторію не вимагайте неможливого self-approval. Доступність правил залежить від тарифу приватного репозиторію. Документація не означає, що правила вже застосовано.

## Перед релізом

1. Збережіть резервну копію робочої БД.
2. Переконайтеся, що `BOT_TOKEN`, `DATABASE_URL` та `OWNER_ID` задані в середовищі хостингу. Виконайте `python -m queue_bot.check_config`. Дивіться [CONFIGURATION.md](docs/CONFIGURATION.md).
3. Перевірте міграцію на тестовій копії. Нове поле `users.banned_until` додається без очищення даних.
4. Зливайте реліз і розгортайте тільки після перевірок. Автоматичного merge/deploy цей процес не налаштовує.
5. Ведіть зміни в GitHub; автоматичні розсилки про оновлення студентам заборонені AGENTS.md.

## Бан і режими

Картка користувача або студента в черзі → «⏳ Бан на N днів» → число 1..36500 → підтвердження. День означає 24 години. Час зберігається в UTC, показується за Києвом. Заблокований студент знімається з активних черг, історія зберігається. Після строку доступ відновлюється під час перевірки доступу, без окремого таймера; старі місця не відновлюються. Є безстрокове блокування та ручний розбан. Адміністраторів спершу потрібно позбавити прав через керування адміністраторами.

«👤 Режим студента» та «⚡ Режим адміна» перемикають поточну чергу. Незавершений ввід скасовується. Права визначає сервер. Якщо чергу вже архівовано, бот повертає в меню.

Бот відхиляє відомі голоси заблокованих і оновлення їхніх приватних бюлетенів. Telegram не передає особу виборця в анонімному груповому опитуванні, тому заборону участі конкретної людини в такому зовнішньому бюлетені бот гарантувати не може.

Повторні обміни та чинне приховування попередніх замін є погодженою поведінкою й захищені регресійними тестами.
